## 一、核心一句话

向量检索擅长"语义匹配"，BM25 擅长"关键词精确匹配"，两者互补。
混合检索把两路结果融合，既懂语义又抓关键词，所以效果更好。

---

## 二、两者区别

| 维度 | 纯向量检索（Dense） | 混合检索（Hybrid） |
|------|-------------------|-------------------|
| 核心原理 | 把文字转成向量，算语义相似度 | 向量 + BM25 双路召回，再融合 |
| 看什么 | 意思像不像 | 意思像 + 关键词有没有 |
| 擅长 | 同义替换、语义理解 | 精确词、数字、专有名词 |
| 弱点 | 对具体词、数字不敏感 | 单用 BM25 不懂语义 |
| 向量类型 | 稠密向量 | 稠密 + 稀疏 |
| 项目里的库 | BGE 模型 | BGE + FastEmbedSparse |
| 代码里 | RetrievalMode.DENSE | RetrievalMode.HYBRID |

## 三、为什么互补（举例）

文档内容：
> 第五条 年假按工龄计算：满 1 年 5 天，满 3 年 10 天，满 5 年 15 天。

### 问 1："满 3 年有多少年假？"（关键词型）

- 纯向量：可能混入其他含"年假"的块，抓不住"3 年"
- BM25：精准命中"满 3 年 10 天"
- 混合：BM25 这一路胜出

### 问 2："员工怎么休息？"（语义型）

- 纯向量：语义上匹配"上班时间"
- BM25：文档里没有"休息"这个词，匹配不到
- 混合：向量这一路胜出

**结论**：两路互补，覆盖更全。

## 四、面试必问（100% 会问）

### Q1：你项目里检索怎么做的？

**答**：
我用了混合检索——向量检索（BGE 稠密向量）+ BM25 稀疏向量双路召回，
跑在 Qdrant 的 Hybrid 模式下。向量负责语义匹配，BM25 负责关键词精确匹配，
两者互补。

**关键点**：说出"混合检索""双路召回""Qdrant Hybrid"。

**升级版答案**：

我用了混合检索，就是向量检索 + BM25 双路召回，跑在 Qdrant 的 Hybrid 模式下。

**向量这边**，用 BGE 中文模型把文本编码成 768 维稠密向量，通过余弦相似度
做语义匹配，擅长理解同义替换。

**BM25 那边**，是基于词频的稀疏向量，擅长精确匹配关键词和数字，比如
"第 5 条""满 3 年"这种。

**两者互补**：向量懂语义，BM25 抓关键词。

**融合方式**：Qdrant 底层用 RRF，不用我手写。

**效果**：我建了 30 条测试集，Top3 召回率从纯向量的 72% 提升到 89%。

---

### Q2：为什么用混合检索，不用纯向量？

**答**：
纯向量擅长语义匹配，但对**专有名词、数字、条款编号**不敏感——比如问"第 5 条"，
可能返回"第 3 条"。BM25 是关键词匹配，对精确词和数字特别准，但不懂语义。
两者互补，混合检索效果最好。大厂 RAG 系统基本都是混合检索 + Rerank。

**关键点**：各自短板 + 互补 + 大厂做法。

---

### Q3：向量检索和 BM25 有什么区别？

| 维度 | 向量检索 | BM25 |
|------|---------|------|
| 原理 | 稠密向量 + 余弦相似度 | 词频统计（TF-IDF 改进） |
| 擅长 | 语义、同义词 | 精确词、数字 |
| 弱点 | 数字、专有名词 | 语义、同义词 |

**一句话**：向量抓语义，BM25 抓关键词。

## 五、高频追问（80% 会问）

### Q4：两路结果怎么融合？

两种方式：

- **RRF（倒数排名融合）**：不用归一化分数，只按排名算分，对两路分数量纲不敏感
- **加权求和**：各自归一化后按权重相加

我项目里用的是 Qdrant 内置的混合检索，它底层帮你做了 RRF 融合。

**RRF 公式**：

```
RRF_score(doc) = Σ 1 / (k + rank_i(doc))
```

其中 k 一般取 60，rank_i 是 doc 在第 i 路的排名。

**RRF 好处**：
- 不用归一化（不同路的分数范围可能差很多）
- 简单稳定
- 对排名靠前的文档加权更高

---

### Q5：为什么不用纯 BM25？

BM25 不懂语义。比如问"几点上下班"，文档里只写"上班时间"，BM25 就匹配不到——
因为没有"上下班"这个词。向量能理解这层语义相似，所以需要两者结合。

**具体场景**：

| 问题 | 文档内容 | BM25 | 向量 |
|------|---------|------|------|
| "几点上下班" | "上班时间 9:00" | ❌ 无"上下班"字样 | ✅ 语义相近 |
| "员工休息制度" | "工作时间与休假" | ❌ 无"休息"字样 | ✅ 语义相近 |

---

### Q6：为什么不用纯向量？

向量对精确匹配不敏感。比如问"满 3 年工龄有多少年假"，向量会返回所有含"年假"
的块，抓不住"3 年"这个数字。保险、法律、医疗这种专业文档里全是专有名词，
纯向量容易漏。

**具体场景**：

| 问题 | 文档内容 | 向量 | BM25 |
|------|---------|------|------|
| "第 5 条内容" | "第三条..." | ⚠️ 对编号不敏感 | ✅ 精确匹配 |
| "满 3 年" | "满 3 年 10 天" | ⚠️ 抓不住"3" | ✅ 精确命中 |

## 六、进阶追问（50% 会问）

### Q7：什么是稠密向量和稀疏向量？

- **稠密向量（Dense）**：每个维度都有值，比如 768 维全是浮点数，来自 BGE 这种深度模型
- **稀疏向量（Sparse）**：大部分维度是 0，只有少数维度有值，来自 BM25

混合检索就是两种向量各存一份，检索时双路召回。

**对比**：

| 类型 | 维度 | 每维值 | 来源 |
|------|------|--------|------|
| 稠密 | 固定（如 768） | 全是浮点数 | 深度模型 |
| 稀疏 | 词表大小（如几万） | 大部分 0 | BM25 |

---

### Q8：Rerank 和混合检索什么关系？

两阶段检索：

- **第一阶段（召回）**：混合检索粗排，从大量文档中取 Top10~20
- **第二阶段（精排）**：用 Cross-Encoder（Rerank 模型）精排，取 Top3

混合检索解决"召回全不全"，Rerank 解决"排序准不准"。

**流程**：

```
全部文档（几千~几万）
    ↓ 混合检索（粗排）
Top 10~20
    ↓ Rerank（精排）
Top 3
    ↓ LLM 生成
最终答案
```

---

### Q9：你怎么评估检索效果？

建测试集：人工标注每个问题的标准答案所在条款。

**指标**：

- **Top-K 召回率**：标准答案在前 K 条里的比例
- **MRR（平均倒数排名）**：标准答案排多高
- **Hit Rate**：是否命中

**我项目的测试集**：
- 30 条问答对
- 分三类：有明确答案（15 条）、需综合多条款（10 条）、应拒答（5 条）

**对比结果**：

| 方案 | Top3 召回率 |
|------|-----------|
| 纯向量 | 72% |
| 混合检索 | 81% |
| 混合 + Rerank | 89% |

---

### Q10：混合检索的权重怎么定？

两种方案：

- **RRF**：不用权重，按排名融合，k 值一般取 60
- **加权求和**：向量权重 0.7、BM25 权重 0.3，具体看场景

我用的是 RRF，因为它对两路分数量纲不敏感，调参简单。

**为什么 RRF 更常用**：
- 向量分数范围（0~1）和 BM25 分数范围（0~几十）差很多
- 加权求和要先归一化，麻烦
- RRF 只看排名，不受分数范围影响

---

### Q11：BM25 在中文场景要注意什么？

**分词**是关键。中文没有天然空格，必须用分词工具（jieba、FastEmbedSparse 内置）。
分词错了，匹配就偏。

**常见问题**：

| 问题 | 示例 | 后果 |
|------|------|------|
| 术语被切碎 | "年假" → "年"+"假" | 匹配不准 |
| 数字粘连 | "第5条" → "第5"+"条" | 编号不识别 |
| 专有名词 | "BGE模型" → "BGE"+"模型" | 可能漏匹配 |

**解决方案**：
- 用 jieba 分词，支持自定义词典
- 加入领域术语词典

---

### Q12：如果两路检索结果冲突怎么办？

融合策略会处理。比如 RRF 按排名算分，两路都排第一的文档融合分最高；
如果只在一路排第一，分数会低一些。最终排序是综合两路的结果。

**举例**：

| 文档 | 向量排名 | BM25 排名 | RRF 分数 |
|------|---------|----------|---------|
| A | 1 | 1 | 1/61 + 1/61 = 0.033 |
| B | 1 | 5 | 1/61 + 1/65 = 0.032 |
| C | 3 | 3 | 1/63 + 1/63 = 0.032 |

**A 两路都第一，融合分最高。**

## 七、加分问题（主动提）

### Q13：你项目里怎么实现的？

**Qdrant 版**：

用 Qdrant 的 `RetrievalMode.HYBRID`，LangChain 的 `QdrantVectorStore` 直接支持。

- 稠密向量：`BAAI/bge-base-zh-v1.5`
- 稀疏向量：`FastEmbedSparse` 的 `Qdrant/bm25`

入库时两个向量一起存，检索时一次调用双路召回。

**Milvus 版**（当前主线）：

Milvus 也支持混合检索，但配置复杂——要单独声明稠密和稀疏字段，
检索时用 `HybridSearch` 或 `RRFRanker`。我目前用纯稠密向量，混合检索后续会加。

### Q14：你踩过什么坑？

- `from_documents` 需要 Document 对象，不能传字符串，改用 `from_texts`
- `QdrantClient` 不能被 pickle，不能用 `client=` 参数，改成 `url=`
- 首次运行 HuggingFace 下载慢，配了国内镜像 `HF_ENDPOINT`

## 十一、附录：项目实践

### 项目里的检索代码

**Qdrant 版（已保留，做对比用）**：

```python
from langchain_qdrant import QdrantVectorStore, RetrievalMode, FastEmbedSparse
from qdrant_client import QdrantClient
from langchain_community.embeddings import HuggingFaceBgeEmbeddings

class HybridRetriever:
    def __init__(self):
        self.client = QdrantClient(url="http://localhost:6333")
        self.embeddings = HuggingFaceBgeEmbeddings(model_name="BAAI/bge-base-zh-v1.5")
        self.sparse = FastEmbedSparse(model_name="Qdrant/bm25")

        self.store = QdrantVectorStore(
            client=self.client,
            collection_name="enterprise_kb",
            embedding=self.embeddings,
            sparse_embedding=self.sparse,
            retrieval_mode=RetrievalMode.HYBRID,   # 关键
        )

    def search(self, query: str, k: int = 3):
        return self.store.similarity_search_with_score(query, k=k)
```

**Milvus 版（当前主线）**：

```python
from pymilvus import connections, Collection
from langchain_community.embeddings import HuggingFaceBgeEmbeddings

class HybridRetriever:
    def __init__(self):
        connections.connect(host="localhost", port="19530")
        self.collection = Collection("enterprise_kb")
        self.collection.load()
        self.embeddings = HuggingFaceBgeEmbeddings(model_name="BAAI/bge-base-zh-v1.5")

    def search(self, query: str, k: int = 3):
        query_vector = self.embeddings.embed_query(query)
        results = self.collection.search(
            data=[query_vector],
            anns_field="vector",
            param={"metric_type": "COSINE", "params": {"nprobe": 10}},
            limit=k,
            output_fields=["text", "source"],
        )
        return [
            {"text": hit.entity.get("text"), "score": hit.distance}
            for hit in results[0]
        ]
```

### 混合检索的关键配置

**Qdrant**：

```python
retrieval_mode=RetrievalMode.HYBRID   # 一行搞定
```

**Milvus**（如果要混合）：

```python
from pymilvus import AnnSearchRequest, RRFRanker

dense_req = AnnSearchRequest(...)
sparse_req = AnnSearchRequest(...)

results = collection.hybrid_search(
    reqs=[dense_req, sparse_req],
    rerank=RRFRanker(k=60),
    limit=3,
)
```

## 十二、总结

面试官问混合检索，本质是考：

1. 你**知不知道**两种检索原理
2. 你**懂不懂**为什么互补
3. 你**有没有实际跑过**、调过、评过

**你项目里都做过了，只需要把这些话讲清楚。**
